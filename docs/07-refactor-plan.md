# 07 · 重构计划与里程碑

## 1. 总体策略

**先立约束，再搭骨架，后搬业务，最后硬化。**

不追求一次性重写；以「可运行、可打包、可验证」为每个阶段出口。硬件相关代码最后动，
纯 UI 与数据层优先迁移。

## 3. 工作流建议

| 事项 | 约定 |
| --- | --- |
| 分支 | `main` 保护；功能分支 `feat/xxx` |
| 提交 | 小步提交，信息含模块前缀，如 `bp: 修复串口超时` |
| 评审 | 每里程碑一次文档 + 兼容性回归 |
| 回归 | 每个 PR 至少跑 typecheck + lint |

## 4. 任务拆分（按模块，便于并行）

| 模块 | 负责范围 | 依赖 |
| --- | --- | --- |
| 基础设施 | 构建、日志、配置、窗口、IPC 框架 | M1 |
| 数据 | 实体、migration、迁移、文件存储 | M2 |
| 血压 | 串口、解析、UI、上传 | M2 |
| B超 | 视频、表单、报告、上传 | M2 |
| 系统 | 驱动、更新、登录、设置 | M2 |
