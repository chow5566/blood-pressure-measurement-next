## 二、技术决策记录（ADR）

> 格式：状态 / 背景 / 决策 / 理由 / 影响 / 待验证。

### ADR-001 · 锁定 Electron 22.3.27

- **状态**：已决定（待正式确认）
- **背景**：需求要求支持 Win7 + 32 位。
- **决策**：使用 Electron `22.3.27`（Chromium 108 / Node 16.17.1 / V8 10.8）。
- **理由**：Electron 22 是最后支持 Win7/8/8.1 的版本；该版本仍提供 win32-ia32 构建。
- **影响**：
  - 接受 22.x 已 EOL、无安全更新；建议内网部署。
  - 主进程为 CJS，不能使用 ESM-only 依赖。
  - 需避免使用 Electron ≥23 的 API。
- **待验证**：无。

### ADR-002 · 本地数据库方案（已确认：better-sqlite3 9.6.0）

- **状态**：已决定（2026-09，已实测）
- **背景**：`sqlite3` 为原生模块，32 位 + Electron 22 的预编译存在不确定性。
- **决策**：采用 **`better-sqlite3@9.6.0`**，通过 `@electron/rebuild` 针对 Electron 22 编译
  ia32 与 x64 两套二进制。
- **理由**：同步 API、性能好、生态成熟；已实测在 Electron 22.3.27（ABI 110）ia32 与 x64
  下建表/读写正常。
- **影响**：打包需按 arch 分别 rebuild；`electron-builder` 的 `npmRebuild` 保持 `false`，
  由脚本显式重建。
- **待验证**：无（已通过）。数据访问层仍建议抽象，便于将来切换。
- **备注**：原候选 `sqlite3` 5.x、`sql.js` 未采用。

### ADR-003 · electron-vite 版本（已确认：2.3.0）

- **状态**：已决定（2026-09，已实测）
- **背景**：需在 Electron 22 / CJS 主进程下构建。
- **决策**：使用 **`electron-vite@2.3.0` + `vite@5.4.21`**，构建目标
  `main/preload: node16`、`renderer: chrome108`。
- **理由**：实测 `pnpm dev`/`pnpm build` 正常；主进程/预加载输出 CJS，适配 Electron 22。
- **影响**：渲染进程不产出高于 Chromium 108 的语法。
- **待验证**：无（已通过）。

### ADR-011 · pnpm 依赖布局（node-linker=hoisted）

- **状态**：已决定（2026-09）
- **背景**：pnpm 默认符号链接布局下，electron-builder 打包后主进程报
  `Cannot find module 'ajv/dist/compile/codegen'`（依赖树收集不全）。
- **决策**：`.npmrc` 设置 **`node-linker=hoisted`**（扁平 node_modules）。
- **理由**：electron-builder 官方推荐；实测修复了打包丢模块问题，且原生模块自动解包正常。
- **影响**：node_modules 体积略增；安装行为更接近 npm。
- **待验证**：无（已通过）。

### ADR-012 · 数据层实现（better-sqlite3 + 自建 migration）

- **状态**：已决定（2026-09，已验证旧库）
- **背景**：旧项目用 TypeORM（`synchronize: true` 自动建表，生产有风险）。
- **决策**：
  - 不使用 TypeORM；直接使用 **better-sqlite3 + 自建 migration runner**。
  - 迁移版本记录于 `schema_migrations(id, name, appliedAt)`，逐版本事务执行。
  - 初始 schema（`001-init`）全部 `CREATE TABLE/INDEX IF NOT EXISTS`，对旧库安全「采纳为基线」。
  - 列名沿用旧库 camelCase，保证旧数据可直接读取。
  - 提供类型化仓库（`repositories/*`），统一预处理语句，禁用 `synchronize`。
- **理由**：去除装饰器/reflect 复杂度与自动同步隐患；SQL 可控、性能好；兼容旧库成本低。
- **影响**：新增字段/表须写新迁移；领域类型集中在 `src/shared/domain`。
- **待验证**：无（已用旧库实测：6 条 B超记录 / 17 图片 / 57 模板完整，integrity ok）。

### ADR-013 · 单窗口架构与启动体验

- **状态**：已决定（2026-09）
- **背景**：用户担心「每开一个窗口都重新加载一次 Vue」，观感不原生。
- **决策**：
  - **单主窗口**：设置/更新/模板选择等一律使用应用内弹窗（Element Plus Dialog），
    不再为每个弹层创建 BrowserWindow。
  - 窗口 `backgroundColor` 跟随页面背景 + `show:false` 到 `ready-to-show`，消除白屏。
  - `index.html` 内置**纯 HTML/CSS 闪屏**，Vue 挂载前即显示，首帧不空白。
  - Element Plus 按需引入，减小首屏 JS 体积。
- **理由**：重复创建 BrowserWindow 才是卡顿主因（Chromium/渲染进程初始化），而非 Vue 体积；
  单窗口同时更省内存，利于 32 位。
- **影响**：弹层改为组件内实现；多窗口同步需求（如旧 `pinia:stateChanged`）不再需要。
- **待验证**：Win7 低端机实测首屏显示时间。

### ADR-004 · 运行权限模型（已确认：普通权限 + 按需提权）

- **状态**：已决定（2026-09，M5 落地）
- **背景**：旧项目整包 `requestedExecutionLevel: requireAdministrator`，仅驱动安装需要提权。
- **决策**：
  - 应用以**普通权限**运行（`electron-builder.yml` 不再设置 `requireAdministrator`）；
  - 驱动安装/卸载通过 `msiexec`，由系统触发 UAC 按需提权（见 `infra/hardware/driver`）；
  - 驱动操作带超时与错误反馈（修复 I5）。
- **理由**：降低安全面与兼容问题；符合 Windows 规范。
- **影响**：首次安装驱动会弹 UAC，需现场告知。
- **待验证**：Win7 32/64 位下 `msiexec` 提权与静默安装表现。

### ADR-005 · ESM-only 依赖治理

- **状态**：已决定（原则）
- **背景**：Electron 22 主进程为 CJS；`electron-store@10`、`uuid@11` 等为 ESM-only，`require` 失败。
- **决策**：
  - `electron-store` 锁定 `8.x`（CJS）。
  - `uuid` 降级到 CJS 可用版本，或统一用 `crypto.randomUUID()`。
  - 新增主进程依赖前，必须确认提供 CJS 入口。
- **影响**：依赖版本可能低于「最新」，属预期。
- **待验证**：逐包检查 `package.json` 的 `exports`/`main`。

### ADR-006 · 移除 `usb` 依赖（已确认：轮询方案）

- **状态**：已决定（2026-09，M3 落地）
- **背景**：`usb` 为原生模块，32 位预编译不确定；现状仅用于 USB 插拔事件。
- **决策**：**移除 `usb`**，改用主进程**轮询** `SerialPort.list()`（默认 3s，仅在列表变化时
  通过 `bp:devices` 通知渲染进程）。
- **理由**：零原生依赖、32 位安全；串口插拔对实时性要求不高，3s 延迟可接受。
- **影响**：插拔检测有轻微延迟；不再需要 WebUSB 权限流程。
- **待验证**：现场插拔体验（可按需调整轮询间隔）。

### ADR-007 · 交付架构（已确认：双架构）

- **状态**：已决定（2026-09）
- **背景**：是否仅出 32 位包，或 32/64 位双包；现场存在 64 位性能诉求。
- **决策**：**同时产出 win32-ia32 与 win32-x64 两个安装包**。
- **理由**：现场既有 32 位也有 64 位机器，且明确存在 64 位性能诉求（64 位进程内存上限更高，
  更适合多图/大图场景）。
- **影响**：
  - 原生模块需分别编译 ia32 与 x64 两套；`electron-builder` 需显式请求两个 arch。
  - 驱动与 VC++ 运行库需按位数分发（x86/x64）。
  - 测试矩阵翻倍，需分别验证 S-M1~S-M10。
- **待验证**：Electron 22.3.27 两个 arch 的原生模块预编译/重编译均可用。

### ADR-008 · 数据存储目录与迁移（已确认细节）

- **状态**：已决定（2026-09）
- **背景**：需求要求安装时可选数据目录、支持换盘迁移；原实现路径固定且不合规范。
- **决策**：
  - 以配置 `dataDir` 为唯一数据根，存放 `database/`、`images/`、`reports/`。
  - 默认 `%ProgramData%\<appName>\data`；**安装时可选 + 应用内可改**（两者都要）。
  - 迁移采用「预检 → 冻结写入 → 复制到临时目录 → 校验 → 原子切换指针 → 删除旧数据 → 自动重启」。
  - **迁移成功后删除旧数据**（不保留备份，删除前二次校验，先改名再删）。
  - **迁移成功后自动重启**（`app.relaunch()` + `app.exit()`）。
  - **禁止**可移动盘/网络盘，仅允许本地固定磁盘。
  - 图片按需压缩（长边 ≤1600px，JPEG 质量 0.75~0.85）。
- **理由**：保证任意时刻原数据完整、可回滚；符合 Windows 数据目录规范；满足换盘诉求。
- **影响**：需引入「维护模式」与配置指针管理；启动需做目录可用性检查与容量预警。
- **待验证**：NSIS 自定义页在 Win7 32/64 位 + UAC 下的表现；跨盘迁移性能；图片压缩后画质。
- **详见**：[10-storage-and-migration.md](10-storage-and-migration.md)。

### ADR-009 · 后端接口冻结与隔离

- **状态**：已决定
- **背景**：后端接口不允许修改。
- **决策**：
  - 保持所有接口路径、方法、字段、响应码、鉴权（`token`）与现有实现一致。
  - 将接口调用集中到 `renderer/src/api/` 的统一客户端，类型化 DTO，禁止散落 axios 调用。
  - 上传失败一律降级本地存储并标记 `isUpload='N'`，支持后续补传。
- **理由**：在冻结契约下，通过隔离层降低耦合，便于测试与替换。
- **影响**：重构不得「顺手优化」接口；如确需变更须走新 ADR 并协调后端。
- **待验证**：无（契约以现状为准）。

### ADR-010 · UI 视觉风格（已确认：A 医疗清新）

- **状态**：已决定（2026-09）
- **背景**：需统一除血压页外的界面风格；血压页视觉冻结。
- **决策**：采用 **A · 医疗清新**：白底卡片、青绿/蓝主色（沿用 `#32ccbc` 与主色
  `#5340ff`）、柔和阴影、圆角，信息层级清晰、亲和。
- **理由**：最贴合体检场景；性能开销小，适配 Chromium 108 / Win7 / 32 位；
  与现有青绿点缀及血压页配色协调。
- **影响**：确定设计 token、卡片/表单/表格/状态色规范，详见
  [11-ui-design.md](11-ui-design.md)。
- **待验证**：多分辨率观感与低端机渲染性能。
